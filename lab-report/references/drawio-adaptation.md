# 将 exp3 视觉规范用于 draw.io

macOS 新图使用 draw.io，Windows 新图使用 Visio。两端共同遵循 [流程图规范](flowchart-guide.md) 和 [exp3 视觉样例](visio-exp3-design.md)；工具变化不降低图形语义、可编辑性、配色、最终字号与连线验收要求。

## 迁移什么

绘图前实际查看所选图型的样例预览。迁移配色角色、主次文字、浅底职责分区、对象表达及回线通道；按本次实验重建节点和关系，不复制旧算法、参数、完成状态或证据。

| 样例表达 | draw.io 中的实现 |
| --- | --- |
| 阶段卡片与底部关键关系 | 原生矩形、独立标题和正文标签、数组单元及连接线；只有确有对应关系时保留底栏 |
| 职责分栏与外侧回路 | 分组或容器加原生流程节点；给条件标签和回边预留通道，分栏本身不代表并行 |
| 状态变化与局部机制 | 原生数组／字段单元、前后状态与局部展开；单元内容仍可单独编辑 |
| 浅色背景与深色标题／描边 | 使用配色表的确切 HEX 值设置 `fillColor`、`strokeColor`、`fontColor`，不用截图取色近似值或默认主题替换 |
| 节点间控制转移 | 连接到起止节点的原生连接线；使用明确的箭头和分支标签，不用端点恰好接近节点的独立线段代替 |

配色角色以样例的 [色值与使用方式](visio-exp3-design.md#配色实际色值与使用方式) 为唯一来源。简单图用少量角色色；多职责图可按需选 2–4 组，同一职责跨图保持一致。设置白色画布，导出时确认编辑器深色主题未改变正式图稿的配色。

## 原生编辑与布局

- 保存 `.drawio` 源文件，保留独立节点、文字、容器和连接线。不能把样例 PNG／SVG 作为单一图片放进画布后称为已经迁移；导入 VSDX 也不自动代表对象和布局无损，须检查实际结果。
- 需要精确复用配色与分区时可直接生成原生 draw.io XML；使用当前可用的 draw.io 工具或技能所公开的接口，不猜测参数。生成的节点与边使用唯一 ID，边的 `source`／`target` 指向实际节点；分组后的连线归属和端点必须正确。
- 常用样式包括 `fillColor`、`strokeColor`、`fontColor`、`fontSize`、`fontFamily` 和正交连线 `edgeStyle=orthogonalEdgeStyle`。字号、线宽、圆角与布局单位不能直接照抄 Visio 的数值；按实际导出 PDF 和报告尺寸重新检查。需要其他格式参数时查当前工具文档。
- 自动布局只作起点，不把已经表达清楚的状态关系、职责分区或对象位置打乱；调整后检查回路、出口标签、交叉、标题区和节点遮挡。原生连接线也不保证自动绕开所有其他对象。
- 同层卡片和数组单元允许等宽等高。通过标题、对象、说明和关系形成层级，不为避免“方框图”而刻意改变同类节点尺寸。
- 先检查可用中文字体。可用时沿用 Microsoft YaHei；否则选择本机可用的中文字体，例如确认已安装的苹方，统一设置并检查公式、换行和 PDF 字形。字体替换不自动改变报告正文的字体规范。
- 不固定使用样例 11.6 in 的宽画布。先确定报告可用宽度，再选择横向、纵向或拆图；在实际 PDF 与报告中检查最终关键文字约 9 pt 以上。预览大图清楚不等于缩入报告后清楚。

## PDF 图稿与后续修改

1. 完成并保存可编辑 `.drawio`，用编辑器重新打开，确认节点和连线可独立编辑；对调整过的节点检查连接是否仍正确。
2. 通过当前 draw.io 应用或支持的导出接口生成正式 PDF。需要通过打印路径保存 PDF 时，检查纸张、缩放、裁边与页数，不能留下额外空白页、截断或把宽图挤成小图。不能把“支持导出 PDF”直接当成此次导出已验收。
3. 从最终 PDF 对应页面生成无损入稿 PNG，并检查中文、线条、比例和必要上下文。按 [流程图规范](flowchart-guide.md) 更新 DOCX 后，查看最终报告中的实际效果。
4. 保留 `.drawio` 工作源文件，即使 PDF 或 PNG 能携带可编辑数据，也不因此删除独立源文件。修改时始终依次更新源文件、PDF、入稿图和当前报告，文件名保持稳定；只维护一套当前源文件。
5. 源文件、正式 PDF 与入稿图放在实验的素材目录；不因绘图工具要求“交付全部格式”而扩大用户约定的交付范围。最终压缩包按教师和用户要求选择文件，默认不含这些制作附件。

这些是工具适配规则，不声称仓库中的 Visio 样例已被自动转换为完全等价的 `.drawio` 模板。实际图形仍须完成结构与视觉验收。
