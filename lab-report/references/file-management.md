# 实验目录、当前报告与提交打包

目标是让用户始终能找到一份当前报告、它所用的素材和可运行实验文件。使用用户指定的实验根目录；当前环境有输出位置限制时，在允许的位置采用此结构。既有项目先检查实际路径和依赖，不擅自迁移其他实验或破坏原项目结构。

## 日常工作结构

```text
实验02_主题/
├── 报告/
│   ├── 实验02_主题.docx          # 唯一当前报告，用户与助手继续修改此文件
│   └── 原始模板/
│       └── 教师提供的原文件名.docx # 或 .doc，保留教师原件
├── 素材/
│   ├── 实验要求/                # 任务书、评分标准等，按需建立
│   ├── 截图/                    # 保留真实原图，裁剪副本与原图明确区分
│   └── 流程图/
│       ├── 实验总览.vsdx        # 或 .drawio，只维护当前采用的一套源文件
│       ├── 实验总览.pdf         # 正式图稿
│       └── 实验总览.png         # 从正式 PDF 生成的入稿图
├── 实验文件/                    # 源码、配置、工程、必要数据与运行资源
├── .work/                       # 助手内部暂存、验收材料与回退副本
└── 实验02_主题.zip              # 仅用户要求打包时生成，名称可按教师要求
```

上述文件名仅为结构示例，沿用用户已经确认的名称与当前实验信息；没有对应材料时不创建空目录。**教师原始报告模板放在报告目录下的原始模板子目录，保留原文件名和内容**，不混入素材或当作当前报告修改。任务书等其他材料放在素材中。

实验文件保持原项目的相对结构，按需包含本地模块、配置、工程文件和必需运行资源，不把依赖文件为了分类好看而挪到素材目录。报告中的说明图、截图与绘图源文件属于素材；程序实际依赖的图像、模型、输入数据属于实验文件。

## 唯一当前报告与持续修改

1. 首次从教师模板制作报告时保留原始模板，建立一份当前 DOCX。后续始终读取用户最新修改的当前报告，不用旧生成稿重建，不按历史文件名或缓存判断哪个版本最新。
2. 当前报告保持固定路径和文件名，不产生“最终版、修改版、v2、v3”等并列稿件。用户明确要求另存版本时才例外；教师最终提交名称在打包时处理，不改当前报告的日常名称。
3. 开始修改时记录当前文件状态，在 `.work` 中建立工作副本和回退副本。默认只维护一份由本 Skill 创建的最近修改前回退副本；不删除用户原有归档、原始模板、证据或其他备份来凑此数量限制。
4. 在工作副本中局部编辑并完成适用的检查。写回前比较当前报告与本次读取时的内容：若用户期间又有修改，先基于最新文件重新应用本次局部改动；无法可靠合并时说明具体冲突，不覆盖用户新增内容。
5. 验证完成后更新同一路径的当前报告，替换操作失败或文件被占用时保留当前文件及已完成的工作副本，说明实际状态；不能把尚未写回的文件称为当前报告已更新。未完成关键版式检查时保留现有主文件，明确待验收工作副本的位置与限制。
6. 交付说明指向这一份当前报告，简短列出修改与未完成项。回退、渲染页、转换中间件、临时脚本和内部检查记录留在 `.work`，不作为常规交付附件或提交文件。

源图和正式导出图同样使用稳定名称。原始截图不覆盖，裁剪或处理副本保留来源对应。报告或核心文件修改后，既有 ZIP 视为过期；仅在用户再次要求打包时重新生成，不将旧包当成最新结果。

## 打包与工作区隔离

**教师的文件命名、目录层级和压缩格式要求只作用于提交副本，不改变上述日常工作结构。** 即使教师要求根目录直接放报告、使用学号命名文件夹、分设 code 和 report，或采用其他结构，也不能据此重排报告、素材或实验文件目录。

1. 以用户已审阅的当前报告与核心文件为准，按 [打包规则](../SKILL.md#最终提交打包) 做一次内部提交前复核。没有新问题就继续，不要求用户重新确认已确认内容。
2. 在 `.work` 中建立本次独立打包暂存目录，复制教师要求及运行必需的文件。仅在副本中调整名称和包内目录；不从整个实验根目录直接压缩，避免带入原始模板、素材、历史包或内部工作文件。
3. 用一份内部对应关系核对“当前工作文件 → 包内路径”，防止拿错旧稿、漏依赖或重复装入。结构调整后仍须满足相对路径依赖；若提交布局与程序依赖确实冲突，指出具体冲突，不通过静默改写已审阅源码来解决。
4. 按教师指定格式和名称生成压缩包；未指定时使用 ZIP，名称与当前报告相同。已有同名交付包时先在暂存位置生成并验证，再更新交付包，不留下多个并列版本。
5. 检查包内清单、完整性、报告和源码与选定版本的内容一致性，并在独立解压目录完成适度的依赖或启动检查。包内结构不同于工作区时检查调整后的实际路径，不能只验证打包前的目录。
6. 正常交付只提供当前压缩包及简短检查结论；内部映射、清单和暂存目录不默认交付。用户或教师明确要求的材料按要求附带。

本规则授权更新当前报告及由本任务维护的当前交付包；不授权修改教师原始模板、覆盖原始证据，或删除用户在其他位置维护的版本。
