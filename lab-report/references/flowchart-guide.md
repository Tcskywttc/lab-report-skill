# 实验总览与跨平台流程图

## 目标与适用范围

让读者在阅读详细操作前看清“做了什么、各阶段如何衔接、产生了什么、哪些结果已得到验证”。新写或补全整份报告必须提供一张实验总览图；Windows 新图使用 Visio，macOS 新图使用 draw.io，二者沿用相同的视觉和验收标准。已有符合要求且清晰准确的图则复用或更新，避免重复。仅排版或局部编辑不自动增加图；用户后续明确更改要求时遵从。

PDF 是正式图稿，DOCX 中使用由该 PDF 转出的清晰页面图。VSDX 或 `.drawio` 作为后续修改的工作源文件保留，不强制独立交付，也不默认加入最终提交包。

优先借鉴软件工程 exp3 中“总览 → 完整控制流 → 局部机制”的层次及浅色职责分区体系。新画或重画图时读取 [exp3 视觉样例与迁移规则](visio-exp3-design.md)，实际查看其中对应图型的预览，再结合本次内容使用；不照搬历史算法、参数、页数或测试结论。图数按解释需要决定，不凑三张，也不为丰富画面虚构分支、循环或并行关系。关键机制可在总览中局部展开，容纳不下时再增加细节图。总览图不能替代教师明确要求的完整程序流程图。

**只要决定画图，就必须按本规范完成设计和验收。** 图须帮助读者理解关键关系，不能只把正文标题放进一串同样的长方形。没有用户样例不构成降低质量的理由；未通过验收先调整，不能把占位图交付为成品。

## 先确定图的内容

- 从实验要求、代码、报告、截图和日志提炼主线。总览优先展示输入／准备、主要处理、关键产物、验证与结果；按实际关系组织，不固定阶段数，不为凑节点添加未做的工作。
- 区分“实验实施流程”和“程序控制流”。前者呈现实验任务及验证环节，后者忠实反映程序的条件、循环和出口。若一张图无法清楚兼顾，前部保留实施总览，算法控制流放在后文。
- 绘图前整理简短的“阶段—产物—证据—状态”对应关系，可留在工作文件中，不强制增加报告表格。图内仅保留读者需要的短标签，正文指向对应截图、表格或验证小节。
- 状态使用有依据的“已实现／已执行／已验证／待验证／待补证据”；设计方案标为“设计流程”或“预期流程”。无状态证据时可只展示流程，并在图旁说明待补材料，不编造完成率。
- 图前用 1–2 句交代它回答的问题；图后简要说明关键路径与验证依据，不把所有节点再抄成一大段。

## 图型与解释层次

- 先确定读者最需要看懂的关系，再选图型：操作顺序用流程图，模块与接口用结构图，字段或信号的处理用数据通路图，运算前后变化用状态示例图，多份证据如何相互核对可用对照图。可组合表达，但保持主线清楚。
- 对有明确内部机制的实验，优先把关键对象画出来，例如位字段、数组单元、端口、模块接口或变换前后的数值。用图形表达数据如何变化，避免只把“对阶、规格化、验证”等正文小标题装进大框。
- 简单递进也可以有层次：主路径交代阶段，关键阶段旁用小范围展开或前后状态说明原理。示例值来自真实材料或明确标注的理论推导；不把推导示例当实测结果。
- 将实验操作、算法内部处理与验证依据分层或分区，按真实关系连接。例如浮点运算可突出字段与移位变化；指令分析可把反汇编与波形通过共同的 PC／时刻对应起来。这些是选图思路，不是每份报告都要套用的版式。
- 用阶段标题、核心图形／数值、辅助注释建立视觉主次，结合分组、对齐、留白和职责配色。同层卡片或数组单元允许等宽等高，关键是呈现对象和关系；避免所有层级都只有同字号的长句，不要仅靠增加颜色或装饰制造复杂感。

## 放置与版式

- 默认放在“方法、步骤”开头的导语之后，早于逐步操作与大量截图。若模板不适合，在“实验过程及内容”开头插入；保持固定章节、封面和教师区域原样。
- 先按报告实际可用宽度设计图。沿用 [排版规范](formatting-standard.md) 的插图宽度、图题与引用规则；表格内扣除单元格边距。用“原图字号 × 插入宽度 / 原图宽度”预估最终字号；exp3 宽画布不能直接缩入报告后便视为合格，必要时减字、增大文字或改纵向／拆图。
- 主路径方向统一，采用从左到右或从上到下的布局。窄版面优先竖向或分区布局；不要把宽大的画布强行缩成看不清的图片。总览尽量与图题同页，细节过多时拆为总览和细节图。
- 白底、清晰边框与少量低饱和配色即可。颜色用于区分阶段或职责，状态仍写文字，不只依赖红绿颜色。图内字体统一，最终插入尺寸下文字建议不小于约 9 pt；这属于可读性建议，不是原样例的实测规范。
- 控制流使用常见语义：起止用圆角框或椭圆，处理用矩形，判断用菱形，输入输出用平行四边形；概览可使用分组模块。条件边标“是／否”或具体条件，循环回边与汇合点必须明确。
- 连线避开文字与节点内部，不以相交暗示汇合。特别检查箭头朝向、折线拐点、返回路径和分支标签，避免出现“线接近节点但未连接”或箭头指错分支。

## 视觉设计与质量门槛

- 绘图前先确定图型、阅读方向、分区层次和颜色含义。已有用户认可的视觉样例时实际查看并沿用其视觉原则；不能仅因文件名含“样例”就声称已参考。无样例时按本规范设计，不等待用户补样例才开始。
- 形状服从语义，不为凑形状强加菱形、椭圆或分支。控制流按上述符号绘制；结构图的同类模块可以使用矩形，但必须靠分组、接口、数据标签或局部机制表达关系，不能全图只是同尺寸文字框串联。
- 同层节点对齐、间距一致，节点尺寸随内容合理调整；用短标题和必要注释区分主次，避免所有文字同字号、长句塞满框。连线采用清晰直线或正交折线，尽量避免交叉，分支标签不能贴在节点文字上。
- 配色默认采用 exp3 的白底、深色正文、浅色分区与对应深色标题／描边体系，具体 HEX 色值见 [配色表](visio-exp3-design.md#配色实际色值与使用方式)。简单图用一个主色与一个强调色即可；有明确职责分区时可选蓝、青绿、琥珀、紫中的 2–4 组，按需使用，不凑满四色。同一职责跨图及局部展开保持一致，关键小字优先用深色正文色。禁止每个节点随机换色、无语义的彩虹色、浓重渐变或低对比度文字。
- 总览可用“阶段卡片 + 关键关系底栏”，控制流可用“职责分栏 + 外侧回路”，机制图可用“状态变化 + 局部展开”。先预留标题、条件标签与回线通道，再排节点；职责分栏不代表并行。上述是可选构图，不是所有实验都要套用的固定布局。
- 有几何、时序、字段、信号或状态变化等核心机制时，在总览中作适度展开，或增加一张局部机制图；仅换框形和颜色不能替代解释力。无此机制时保持简洁，不虚构细节。
- 先查看导出图，再按报告实际插入宽度查看渲染页。检查文字是否拥挤或过小、是否有截断遮挡、连线是否清楚、布局是否均衡、颜色是否有一致含义。任何一项不合格必须先修图并重新导出；源文件能打开或像素数量足够都不能代替视觉验收。

## 跨平台制作与导出

1. Windows 使用 Microsoft Visio 保存 `.vsdx`，macOS 使用 draw.io 保存 `.drawio`，均须使用可单独编辑的形状、文字和连接线，不能把整张图作为一个图片对象冒充可编辑源图。Mac 制作前读取 [draw.io 适配规则](drawio-adaptation.md)。已有图继续以原有源文件为准，不因换电脑就同时维护两套主源文件；格式迁移须核对对象、文字、条件与连接关系。源文件留作修改，不强制交付。复用 [exp3 VSDX](../assets/visio-exp3/exp3-flowchart-reference.vsdx) 时另存副本；它含历史算法和手工折线，不是空白模板，移动节点后须重接或核查连线。
2. Windows 上可通过已安装 Visio 的 COM 接口自动化，例如 `Visio.InvisibleApp`。操作专属文档副本，只关闭本次创建的应用实例；不关闭用户已有的 Visio 会话。历史实验脚本只能作参考，不能直接运行其中的旧路径、旧材料和覆盖操作。
3. 从最终 VSDX 或 `.drawio` 源文件导出 PDF 作为正式图稿，检查页面边界、文字、字体、连线及留白。DOCX 中嵌入从该 PDF 对应页面转换出的无损 PNG，按最终插入尺寸准备约 300 dpi 的像素量，并以实际阅读效果验收；多页 PDF 按所需页面分别取图。不得截 PDF 查看器窗口、插入附件图标或只给外部链接来代替报告中的图。若已存在的合格图只提供了正式 PDF，可直接据其入稿；需要修改而缺少源文件时如实说明。
4. 图形修改后依次更新当前可编辑源文件、PDF、入稿 PNG 和 DOCX，保证内容一致，不使用旧的导出图。工作源文件和导出文件沿用稳定名称，图号按报告统一编号，如“图 1  实验总体流程与验证环节”。
5. 根据当前平台检查对应绘图工具；macOS 使用 draw.io 已获用户确认，无需再次请求替代 Visio 的许可。教师或本次用户明确限定 Visio 时遵从该特定要求，不能把 draw.io 图宣称为 Visio 制作。所需工具不可用时继续其他已授权工作，并说明图形制作尚未完成；不为此自行安装、购买软件或未经授权跨设备操作。

## 验收与交付

- 内容：沿箭头逐步检查实际顺序、判断、循环、终止与验证环节；图中状态与证据一致，概览中的简化不改变关键含义。
- 工作源文件：新制作或修改的图在对应编辑器重新打开 VSDX 或 `.drawio`，确认页、文字、节点与连线存在并可编辑；此为内部复用检查，不意味着必须交付源文件。未完成检查时说明限制；复用既有正式 PDF 且不修改图形时，不凭空声称已检查其源文件。
- 图形：分别查看正式 PDF 和由它生成的入稿图，检查中文字体、遮挡、截断、箭头、分支标签和留白，并核对页面及内容一致。
- 解释力：检查读者能否从图中直接看出关键关系或变化。若图只是把步骤清单换成方框，且材料中有值得展示的机制，应改用更合适的图型或局部展开；若任务本来只有简单顺序，保持简洁即可。
- 报告：渲染插图所在页和受分页影响的后续页，按最终阅读尺寸检查清晰度、图题同页、编号和正文引用，同时完成模板保护核验。不能以单独导出图好看代替报告内验收。
- 交付：唯一当前 DOCX，并保留正式 PDF 图稿供用户查看；VSDX／`.drawio` 与入稿 PNG 作为工作素材保留，不强制列为交付附件。只有用户或教师要求时才将这些独立图形文件放入最终提交包。简短说明总览图位置、待补证据及未完成验证，工作脚本与中间图不混入提交材料。
