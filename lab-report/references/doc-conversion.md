# DOC 模板转换与保真检查

适用于旧版 `.doc` 教师模板。先取得可靠的可编辑副本，再插入正文；不在失真的副本上完成整份报告。

## 转换与编辑

1. 保留原件。在可正确显示原件的 Word／WPS 等原生应用中查看封面、教师区域及其他固定结构，记录空白下划线、表格、字体、页边距、分节、页眉页脚和分页；必要时保存工作用截图或 PDF 作为视觉基准。
2. 优先用当前可正常保存的原生应用另存为 DOCX 工作副本。无需先尝试已知不可用的应用；不为转换自行购买、激活软件或上传材料。
3. 重新打开转换副本，与原始 `.doc` 的原生显示对照。确认固定区域、空白填写线、表格和分页保留后，再以副本为底稿编辑。保存成功、文字相同或 XML 一致均不能单独证明转换保真。
4. 保留保护区域节点及依赖的共享样式、兼容设置、节属性、页眉页脚和媒体关系。按实际内容识别插入点，不照搬历史段落下标；合入正文时处理图片、超链接关系 ID 和媒体名称冲突。
5. 完成后同时做结构与视觉检查，查看全部受影响页面及首尾衔接。正文变长允许自然分页，保护区内容与必要可编辑性保持不变。字体缺失或无法取得可靠原生显示时如实说明未完成的验证。

## 避免重复发生的转换问题

- 历史 Mac 任务中，部分旧模板依靠带下划线的末尾空格及兼容设置显示填写横线；通用转换副本曾丢失长横线，而 WPS 原生另存保留了表现。这是已发生的特定案例，不保证其他模板或应用版本相同。
- 可检查 `word/settings.xml` 的 `w:compat` 及 `w:ulTrailSpace` 等相关设置，但不直接复制历史文件的全部配置，也不认为补一项设置即可保证正确显示。
- 同一引擎既转换又渲染，可能在原件与副本中显示同一种缺陷。可用其辅助检查正文，但必须对照原件的可靠原生显示，不能仅据该引擎的前后结果判定保真。
- 不为迎合失真的预览破坏原生显示；记录实际差异，不在没有证据时归因于 Mac 或 Windows 本身。

## 转换不可靠时

- 优先保留可靠、可编辑的原模板固定区域，另行准备正文；固定区域不止首尾两页时须全部保留。
- 封面和教师区域默认仍需用户手工填写。无法可靠保留其可编辑性时，交付原模板与独立正文，并说明合并尚未完成；不默认把固定区域转成整页图片。
- 仅在用户已接受不可编辑固定页的情形下，才采用从可靠原生显示导出的 PDF 页面或清晰整页图像。保持原比例，检查二次页边距、裁切和重复页码；保留原模板，不从失真的转换结果取页。
- 无法获得原件的正确显示时，继续准备可完成的独立正文，明确缺少的条件，不声称固定页已保真或整份报告已完成。

交付说明简短记录所用转换应用、实际完成的检查、采用的降级方式和未完成项；截图、对照 PDF 及中间转换文件留在工作材料中，不默认作为提交附件。
